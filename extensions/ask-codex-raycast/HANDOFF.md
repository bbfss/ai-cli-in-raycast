## Implemented

- `command-routing.ts` maps each command to a provider. An old active-provider preference cannot redirect a named command. Cross-CLI switching saves the current state and uses Raycast `launchCommand`, which respects native command disablement; prompts and conversation data are not forwarded.
- `provider.ts`: shared ChatClient contract and capabilities. Codex retains its app-server implementation and is the only provider with steering. Effort choices come from each exact model's verified catalog, rather than a provider-wide hardcoded switch.
- `provider-antigravity.ts`: native `agy`, live model discovery, explicit conversation mapping, stream parsing, bounded output, timeout and process-tree cancellation. Completion waits for process close and mapping persistence. Unexpected resumed IDs fail without overwriting saved mappings.
- `provider-cli.ts`: Qoder, Qoder CN, WorkBuddy and Gemini subprocess lifecycle, bounded mapping persistence, exact resume, cancellation, overlap protection, and explicit terminal success. Process exit 0 alone is insufficient.
- The input popover has separate Model and Effort menus. Opening the popover or either menu refreshes the catalog, including when a cached catalog exists. Loading/error states remove old selectable choices. A new reply rechecks its explicit model/effort; running-turn steering keeps the original model. Old callbacks cannot select during sends or command transitions.
- Model and effort options continue into message entry through lazy native submenus instead of closing the action panel. Main shortcut menus and popover menus share the same `ComposerInput` handle and draft/pending/revision state. Only accepted selections activate a branch. Keep the active input branch mounted across catalog refreshes/errors/model removal while hiding other stale choices; otherwise a refresh would remove its native ancestor and dismiss the popover. Reopening a picker or root input releases old lazy branches. Synchronous picker epochs, unique activation tokens and mounted guards retire old callbacks before React removes a branch, including selecting the same model again; a retired callback must not reset or overwrite the shared current draft. There is no public SDK pop-parent API: native Escape follows the resulting submenu stack, and consecutive choices can add levels until send/close.
- `CLI Settings` lists six CLI commands first and Preferences last. Its primary row action opens that CLI without forwarding prompts/context; model defaults are second. Launches respect host command disablement and use pending/unmount guards. Raycast's own extension preference page has no public Commands/Preferences layout control; do not claim to reorder that host page by moving manifest keys.
- The user's final screenshot explicitly points to the human role label “You”: add the small person avatar there. `chat-text.ts` now displays the existing generic `user-avatar.svg` beside human messages and additional instructions, with the same 18px inline `<sub>` treatment as AI headings. Provider logos are also supplied to message-entry and send actions as an accepted extra. Native Windows displays them in the expanded input action and send row, but not on the host-drawn footer button. Do not reinterpret the requested human avatar as another provider or footer icon.
- Native Raycast preferences expose a last/fixed model strategy for each CLI. The fixed model/effort is selected dynamically in `model-settings.tsx` from CLI Settings; the host preference schema cannot provide runtime CLI catalogs. Fixed choices are checked again before saving and on sending. Opening a CLI or starting a new chat reapplies its fixed choice; in-chat model changes remain temporary. Last mode remembers a concrete model/effort even for Use Current Conversation Model. The policy has its own provider-scoped key and preserves original model/history keys.
- WorkBuddy's selected embedded bundle supplies exact chat-model metadata through `cli/product.json`, bounded to 1 MiB and its own real directory. Explicit `reasoning.supportedEfforts` is exposed only when that CLI's help also advertises `--effort`, and the selected level is passed through argv. Local CLI 2.161.0 exposes 23 catalog choices, 12 with explicit effort lists; this is not an entitlement or sign-in check. AGY 1.4.4 and Qoder CN 1.1.74 have global effort flags but their public model lists do not publish per-model levels. Preserve their empty effort lists and AGY's distinct low/medium/high model IDs. Gemini CLI 0.65.0 keeps CLI Default without an invented catalog.
- `cli-protocols.ts`: separate Gemini vs Qoder/WorkBuddy event schemas. Ignore reasoning, tool payloads and nested subagent sessions. Never implicitly resume the globally latest session.
- `cli-executable.ts`: native/known npm Node entrypoint discovery without shell prompt interpolation. Handles Windows extensionless npm dispatchers as well as `.cmd` wrappers. Custom WorkBuddy bundles use a process-only bundle selector. Node must be available on PATH.
- `executable.ts`: preserve all environment settings while handling mixed-case Windows `Path`/`AppData` keys without duplicate PATH entries. Antigravity auto-detection includes its standard LocalAppData install.
- `session-storage.ts`: history/drafts/model/setup isolated by provider, original Codex keys preserved. Mapping keys retain the original AGY format.
- `cli-hub.tsx` launches independent CLI commands without forwarding prompts or sessions. `cli-settings.tsx` uses a native List and Metadata inspector for discovered paths and status. Detection results mean file discovery, not authenticated inference.
- Automatic detection defaults to true. Explicit per-CLI paths take priority, including reporting a bad configured path instead of falling back. With detection off, every CLI needs an explicit path. The setting is respected by both discovery screens and chat client creation.
- Opening CLI Settings from chat waits for conversation, draft, and model saves; a running reply must be stopped first. Failed saves or unmounts do not launch a different command.
- `i18n.ts` defaults to Follow System (`system`), reading `Intl.DateTimeFormat().resolvedOptions().locale` and resolving Chinese script through `Intl.Locale.maximize()`. Hans uses simplified Chinese, Hant uses traditional Chinese, and other languages use English. Explicit `en`/`zh-CN`/`zh-TW` choices override the system and retain their existing preference values. Missing preferences follow the system; unsupported nonempty values fall back to English. Runtime chats, launcher and CLI Settings use the resolved language after reopening. All native preference titles, descriptions, checkbox labels and dropdown choices use static Chinese-first bilingual text, as do extension/command descriptions and prompt placeholders. Raycast 2.8.2 supports only English for its own UI, and the public SDK exposes no host language setting. Generated missing-path/unsupported-format guidance and empty history titles follow the resolved language; user titles, prompts, AI responses and actual CLI diagnostics remain intact.
- The user's latest instruction rejects flattened List-row chat and editor-page navigation. Chat is restored to a full-width native `Detail` with Markdown code blocks, lists and formulas. `message-composer.tsx` uses an `ActionPanel.Submenu` input popover above the bottom-right action bar: Enter opens it, typing followed by Enter sends, and the conversation remains visible without a navigation push.
- Latest question-and-answer groups come first, each question before its answer; earlier exchanges remain below. Replies render Markdown directly rather than becoming List rows. Stored and copied content stays unchanged. Stop Response is an explicit action, never the default Enter action. Codex supports steering; other CLIs permit drafting but require manual send after completion or stop.
- The user ultimately preferred the earlier simple divider style; do not add round numbers or extra reply labels. Questions keep their original quote block and replies keep their aligned provider header. Only the extension inserts inter-exchange horizontal rules. Assistant-authored thematic breaks are removed by the display-only stripMessageDividers helper; fenced/indented code, math and setext headings are preserved. Stored transcripts and clipboard text stay raw.
- Provider logos sit inline beside the provider name. `chat-text.ts` wraps the 18px Markdown image in standard `<sub>` markup to align its vertical center with the text. This was verified in the native Windows view; do not replace it with unverified CSS or a separate image block.
- Draft revision, mounted and pending guards protect newer edits from late acknowledgements and duplicate sends. The parent draft remains until acknowledgement; failed sends preserve it and Clear Draft explicitly discards it. A saved draft's preview is included in the explicit Send Saved Draft action, with no second hint/preview section above it. Copy Draft to Continue Editing copies saved text for pasting into the native input. The submenu search is uncontrolled: public APIs cannot refill it programmatically. Do not claim persistent multiline input or Shift+Enter editing; an existing multiline saved draft can be sent intact through its explicit action. Neither the installed SubmenuProps nor the official public API provides a highlighted-row callback or a search placeholder override; the native heading changes when entering a submenu, not while merely highlighting its rows.
- Two-stage setup uses native Forms: with detection enabled, the first mount automatically checks connection/catalog without sending an inference prompt; the next form requires an explicit valid model and supported effort choice. A saved valid choice is preserved. Manual mode retains an explicit check action. Deferred startup and unmount guards prevent duplicate development mount launches and work after leaving setup. CLI Default is an explicit option where no reliable catalog exists.
